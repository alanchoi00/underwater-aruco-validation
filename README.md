# underwater-aruco-validation

Standalone toolkit for validating underwater **ArUco** marker detection and pose
estimation on a BlueROV2, decoupled from the docking controller. It covers the
capture-to-analysis path: generate a print target, record a pool run, and characterise
detection vs range and marker size offline.

This repo is **independent** of the docking pipeline — it runs its own `cv2.aruco`
detection and carries its own marker definitions; it does not import any controller or
perception packages.

## Layout

```
collage/    aruco_collage_a4.py    true-scale A4 ArUco print-target generator
config/     marker_sizes.yaml      id -> NOMINAL black-square size (m); regenerated by the collage
recorder/   record_bag.sh          rosbag capture for a pool run
docs/       capture_2026-07-02.md  what the 2026-07-02 pool session actually recorded
print/      aruco_collage_A4.pdf   generated print target (true-scale markers across A4 sheets)
```

Analysis code (detection sweep, board bundle, metrics) is added under `analysis/` — see
its own README once present.

## Dependencies

- Python: `numpy`, `opencv-contrib-python`, `reportlab`, `pyyaml` (`pip install -r requirements.txt`)
- ROS 2 (for `record_bag.sh` only): `ros2 bag`, from your ROS 2 install, not pip.

## Quick start

Generate the print target (defaults match the dock: Original ArUco dict, dock IDs/sizes):

```bash
python3 collage/aruco_collage_a4.py --out print/aruco_collage_A4.pdf
```

Print at **100% (actual size)**, then **caliper the printed markers and record the real
sizes**. Do not skip this: the 2026-07-02 board printed at ~95.9% ("fit to printable
area"), which shifts every derived range by that factor. The generator writes
`config/marker_sizes.yaml` from nominal sizes and overwrites it on every run, so a
measured correction belongs in a separate file, never there.

Record a pool run:

```bash
recorder/record_bag.sh alan-3        # -> $DATASET_DIR/alan-3
```

Before diving, confirm the camera and odometry are actually publishing:

```bash
ros2 topic hz /zed/zed_node/left/image_rect_color/compressed
ros2 topic hz /zed/zed_node/odom
```

## On ground truth

The 2026-07-02 capture recorded **no ground truth** — range and heading were never
measured, and ZED odometry was not in the bag. `record_bag.sh` fixes this by recording
`/zed/zed_node/odom` and `/zed/zed_node/pose` (ZED visual-inertial odometry, a metric
trajectory). Record them. Without a metric reference, detection range can only be
reported against the ArUco pose itself — the thing under test — and translation accuracy
is not measurable at all. See `docs/capture_2026-07-02.md`.
